# AGENTS.md

Этот файл обязателен для любого AI-агента, который начинает работу в репозитории.
Главная цель: работать предсказуемо, безопасно и с актуальной документацией.

## 1) Обязательный стартовый порядок (нельзя пропускать)

Перед любыми действиями агент ДОЛЖЕН выполнить шаги строго по порядку:

1. Прочитать `readme.md` целиком.
2. Прочитать ВСЕ файлы в папке `/docs` целиком (рекурсивно, включая подпапки).
3. Коротко сверить задачу пользователя с тем, что найдено в `readme.md` и `/docs`.
4. Только после этого начинать изменения кода, запуск команд и редактирование файлов.

Если папка `/docs` отсутствует:
- агент должен явно сообщить об этом пользователю;
- продолжить работу по `readme.md` и коду;
- при значимых изменениях создать/обновить документацию в `/docs` (см. раздел ниже).

## 2) Обязательное обновление документации

Если агент вносит значимые изменения в проект, он ОБЯЗАН обновить `/docs`.

Считать изменения значимыми, если изменилось хотя бы одно:
- поведение функции или бизнес-логики;
- публичный API, контракты, форматы данных, события;
- архитектурные решения, структура модулей, важные зависимости;
- процесс запуска, сборки, деплоя или окружения;
- правила разработки, ограничения, сценарии использования.

Минимальные действия агента при значимых изменениях:
1. Найти релевантный файл в `/docs` и обновить его.
2. Если подходящего файла нет, создать новый файл в `/docs`.
3. Добавить кратко: что изменено, зачем, как использовать/проверить.
4. Проверить, что документация не противоречит `readme.md`.

## 3) Лучшие практики промптинга (как агент должен работать)

Агент должен:
- писать и выполнять план маленькими проверяемыми шагами;
- сначала уточнять цель, ограничения и ожидаемый результат;
- давать конкретные, проверяемые ответы вместо общих формулировок;
- явно фиксировать допущения, если данных не хватает;
- использовать короткие списки и понятные форматы результата;
- после изменений делать проверку (тесты/линт/запуск релевантных команд).

Для сложных задач:
1. Разбить задачу на этапы.
2. Выполнять по одному этапу.
3. После каждого этапа сверять результат с требованиями.

## 4) Правила качества и безопасности

- Не делать разрушительные действия без явного запроса пользователя.
- Не менять несвязанные файлы без необходимости.
- Не выдумывать факты: если неизвестно — прямо сказать и проверить.
- Предпочитать точечные изменения вместо большого рефакторинга без запроса.

## 5) Формат финального отчёта агента

В конце задачи агент должен кратко сообщить:
- что сделано;
- какие файлы изменены;
- как это проверить;
- какие файлы в `/docs` обновлены (или почему не обновлялись).
